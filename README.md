# ScanSplit PDF 1.10.0 — 扫描件拆分与命名工具（Windows 离线版）

把混合扫描 PDF 拆成单份文档，提取每份的**标题**与明确标注的**填报单位**，
按 `标题——单位.pdf` 命名并导出。**全程离线运行，绝不修改源文件，导出像素级保真。**

核心流程：**导入 → 自动拆分 → 检查方向与边界 → 命名 → 检查清单并导出**。

**可靠性优先于自动化程度。无法确定的结果必须暴露给用户确认，绝不静默猜测、覆盖或丢页。**
详细操作与验收范围见 [使用说明](work/reliable-user-guide.md)。

## 功能

- **导入**：文件选择器多选或直接把 PDF 拖进窗口（Windows 原生拖放）。
- **空白页检测**：多信号图像分析（墨迹比/深色比/梯度比/内容包围盒），自适应阈值，
  抗扫描阴影、噪点、边缘黑线；印章、浅色签名等一律判为"疑似"由人确认，绝不武断删除；
  阈值可在设置中调整，每页判定依据可右键查看。
- **自动拆分**：统一检查空白、方向、印刷页码、首页结构、续表附件和填报单位变化。
  无空白页的连续文件也使用同一入口。双信号一致且无冲突时建立保留原页的拆分点；
  单信号、冲突、无法识别的文字进入待确认清单。不确定边界默认不拆，所有空白默认保留；
  排除分隔空白需要用户明确确认，首尾空白也不例外。
- **旋转**：横版表格页支持 90/180/270° 旋转（单页/Ctrl 多选/整组），
  导出时仅写入 PDF 页面 `/Rotate` 属性，**绝不重绘页面**；
  "识别方向"对全部非分隔页做 OCR 方向分析（页面尺寸一致也会查），
  用检测框横竖行几何 + 禁用角度分类模型的 OCR 质量对比给出建议，
  建议不会直接生效，用户可逐页确认，或检查后批量保持当前方向。
- **OCR 自动命名（本地）**：标题识别综合字号（≥4% 页高）、水平居中、页面位置、
  公文标题格式、OCR 证据分数，支持多行标题拼接。填报单位只取明确标签和邻近值；
  文头、落款、印章与正文中的单位不能替代。没有标签留空，多个不同值要求人工裁决。
  先确认分组和方向，再命名；来源页与区域可在预览查看，字段可快速确认或修改。
- **导出**：pypdf 复制原始页面对象（内容流与嵌入图像字节原样保留），逐份校验
  输出页的解码内容流哈希 + 原始编码流哈希 + 图像哈希 + 页面映射（读取异常直接判失败），
  并做**全局页面覆盖率校验**（每个有效原页恰好导出一次，漏页/重复页立即告警），
  源文件导出前后 SHA-256 复检；重名自动加 (2)；**严格导出模式默认开启**——
  空标题、空单位或存在待确认结果时阻断正式导出；底层强制页面完整性检查，部分导出也不能绕过。
  每次生成逐页去向 JSON 记录。支持取消，已验证完成的文件保留。
- **交互**：左侧缩略图（空白/疑似/分隔徽章），中央大图预览（适应窗口/实际大小/
  Ctrl+滚轮缩放/拖拽平移/翻页/旋转预览，按系统 DPI 渲染保证高分屏清晰），
  右侧分组面板（标题/单位编辑、OCR 候选下拉、置信度与"待确认"徽章、实时文件名预览）；
  撤销/重做（Ctrl+Z / Ctrl+Y）、左/右键翻页、Delete 切换分隔页。
- **离线与安全**：OCR 模型随程序分发，启动时 SHA-256 完整性校验，运行时绝不联网、
  不调用任何云端 API；OCR 只读渲染图像做临时识别，**识别文字绝不写回 PDF**。

## 安装（离线）

要求：Windows 10/11 x64，无需 Python 环境即可使用打包版。

**方式 A：直接运行打包版**（推荐）

1. 解压 `dist/ScanSplitPDF.zip`；
2. 双击 `ScanSplitPDF.exe`（首次启动约 2~5 秒加载 OCR 模型）。

**方式 B：源码运行**（需要 Python 3.14 x64）

```bat
python -m venv .venv
.venv\Scripts\python -m pip install -r requirements.lock.txt
run.bat
```

依赖安装需在有网环境一次性完成，之后运行完全离线。

## 使用流程

1. **打开 PDF**（可多选/拖入）→ 左下缩略图浏览；
2. **自动拆分** → 方向建议与边界草稿，不确定结果进入清单；
3. **检查拆分** → 预览前后页，确认方向、拆开或继续同一份；排除空白需明确确认；
4. **OCR 自动命名** → 检查标题和填报单位，可查看来源、选择候选、修改或确认；
5. **导出全部** → 检查勾选清单 → 校验并导出；输出目录包含原页去向记录。

## 技术选型

| 组件 | 选择 | 理由 |
|------|------|------|
| 界面 | Python 自带 Tkinter/ttk | 无额外 GUI 依赖，PyInstaller 打包成熟 |
| PDF 读写 | pypdf（BSD） | 页面对象级复制天然保真；避免 AGPL 的 PyMuPDF |
| 渲染 | pypdfium2（BSD/Apache，PDFium） | 高质量渲染供预览/检测/OCR |
| OCR | rapidocr-onnxruntime + PaddleOCR 官方 PP-OCRv3 中文模型（Apache-2.0） | **PaddleOCR 官方包依赖 PaddlePaddle，截至 2026-10 尚无 Python 3.14 Windows 轮子**；RapidOCR 用 ONNX Runtime 直接跑官方模型，模型随包分发、完全离线；Tesseract 作为备选方案评估过（中文识别率低于 PP-OCRv3） |
| 空白检测 | 多信号模型（借鉴 MIT scanprep 思路重写） | 自适应阈值+边缘裁剪+形态学，扩展深色比/梯度比/包围盒多信号三级判定 |
| 打包 | PyInstaller | onedir 模式，模型与 DLL 一并打包，无运行时下载 |

参考仓库调研（详见 `research/NOTES.md`）：pdf-split-and-rename（Web PWA，需 CDN，弃）、
scan-pdf-cleaner（MIT，思路验证）、pdfarranger（GPL-3，仅参考交互设计，未用其代码）、
scanprep（MIT，检测算法思路借鉴并重写）。

## 项目结构

```
scansplit/
  loader.py       打开/检查 PDF（加密、签名、批注警告）
  blankdetect.py  空白页检测（多信号 + 三级判定）
  grouping.py     分隔页 → 文档组（纯函数）
  ocr.py          本地 OCR 引擎封装（模型完整性校验）
  ocrfields.py    标题/单位字段提取（几何+公文格式启发式）
  ocrseal.py      公章（红章）文字提取（红色隔离+圆环极坐标展开）
  autoname.py     命名编排、方向分析、边界双重验证
  rotation.py     /Rotate 目标角度管理
  naming.py       文件名模板、非法字符清理、防覆盖、单位历史
  exporter.py     批量导出 + 预检 + 保真校验
  verify.py       内容流/图像哈希指纹与页面映射校验
  model.py        页面/分组/工作区状态与撤销快照
  render.py       页面渲染（预览/检测/OCR 共用，LRU 缓存）
  settings.py     %APPDATA%\ScanSplitPDF\settings.json
  ui.py / ui_widgets.py / main.py   界面与入口
tests/            100 项自动化测试（合成扫描件，绝不使用真实文件）
tools/            模型清单生成、OCR 准确率报告脚本
```

接手本项目（交给其他开发者或 AI 继续优化）前请先读 `HANDOFF.md`：硬约束、架构、
设计决策、版本历史、常见坑、构建部署流程与协作注意事项都在其中。

## 已知限制

- 加密 PDF：仅支持空密码，需密码的文件请先去除密码再导入；
- 数字签名：导出生成新文件后原签名失效（源文件不动，导入时会警告）；
- 表单/批注：页面随复制保留，但不保证表单交互功能完整（导入时会警告）；
- 空白检测对"整页为浅色照片/浅色整页图案"可能判为疑似，属保守设计，请人工确认；
- OCR 对印章覆盖、极端倾斜、低分辨率扫描的识别率下降，不确定字段会标"待确认"，
  程序绝不编造内容——识别不出就留空；
- 分组拆分以空白页为候选，再由上下文（页码/首页结构/续页标记/标题同源）判定是否作为分隔；
  无空白页分隔的连续扫描可用"复核拆分/补拆"自动识别
  （印刷页码重置 + 标题特征双信号一致才自动补拆）；若扫描件既无空白页、又无印刷页码、
  首页标题特征也不明显，则只能人工补拆；
- 界面长任务（检测/OCR）在后台逐页处理时窗口短暂无响应（进度条与取消可用）；
- 拖放导入基于 Windows 消息子类化，个别环境若拖放无效请用"打开 PDF"按钮；
- 打包版为 onedir 目录，需整体拷贝，不支持单文件精简；
- 首次加载 OCR 引擎需 1~5 秒。
