# ScanSplitPDF 1.18 交付报告

基线：`9075a33`，v1.17.1，分支 `codex/reliable-scansplit`。用户最新授权：现有方向建议直接自动回正，再集中审核，取消逐页采用建议的操作。

## 修改前的问题

- 非零方向建议不生效，用户逐页确认后才能继续拆分和命名。
- 高级方向分析另有采用建议弹窗，主流程和高级入口行为分散。
- 回正效果与原件缺少集中浏览、一次确认入口。
- 自动采用与人工确认需要继续保持不同来源，避免重分析覆盖人工设定。

## 修改内容

- `automation.apply_direction_result` 采用现有 OCR 建议作为绝对附加角度，写入 `detected_rotation`；保留自动置信度与依据。没有建议、非法结果或分析失败保持当前角度待处理。
- 自动分析先应用方向，再使用该方向的 OCR 证据检查边界。预览、命名与导出继续共用 `effective_rotation`，源 PDF `/Rotate` 与附加角度分开保存，重复运行不叠加。
- 审核窗口新增“复查自动回正”：连续全页浏览、原件/自动结果对照、当前页纠正、一次确认本批方向。浏览与列表原页码同步。一次确认方向不确认文件归属、标题或单位。
- 保留现有 0.75 门槛与明确正放检查：低把握建议也先应用，但标记重点复查，确认前不允许正式导出或当作命名已可靠；可集中一次确认。明确正放且通过原有四方向规则的页面不增加点击。
- 自动状态与人工状态分别展示。人工方向不被自动覆盖；相同角度的集中确认不会让已正确的证据失效，真正纠正角度才要求更新分析。未确认文件范围不会被方向批量确认顺带通过。
- `exporter.py` 仅扩充已有方向准入检查，识别新增“已应用但待复查”状态，防止直接 API 或部分导出绕过。没有改复制原页、保真验证、覆盖率、覆盖文件保护或导出去向算法。OCR 引擎、方向评分、拆分判断和命名规则未改。

## 流程变化

旧：分析 → 逐页采用方向 → 再分析 → 检查拆分 → 确认名称 → 导出。

新：分析时自动回正 → 浏览回正效果，必要时一次确认并只纠正错误页 → 检查拆分 → 确认名称 → 导出。

## 验证与限制

最终 pytest、真实离线 OCR 样张与独立运行包验证见当前 `TEST_REPORT.md` 及包内 `版本与验证.json`。

完整回归：490项通过，331.68秒，0失败/跳过，无警告；新增29项状态、事务、方向、导出准入与真实Tk交互回归。构建成功，新EXE自检与图形窗口启动/关闭均返回0，21个嵌入模块、本地模型/配置及Tcl/Tk核对通过。

五页合成样张覆盖正常、侧放、倒置、反向侧放，以及原 PDF 自带旋转；实际方向角度全部符合已知样张，源件 SHA 不变。样张的四处页码交界仍被规则列为待确认，验收显式模拟独立文件归属批准后再命名和导出，没有把方向通过当作拆分通过。该样张没有实测真实业务总体准确率，也不证明方向识别达到 100%。

实际原生 UI 验证包括最大化整页、1366×700 原件与回正对照、原 PDF 旋转、批量方向确认后返回文件检查。只抓取本程序自身窗口。

保留旧版本包。数百页实际使用、另一台干净 Windows 与关闭后恢复项目仍未验收或实现；本轮没有扩大到这些功能。
