# ScanSplitPDF v1.12.0 UI/UX 交付报告

日期：2026-10-12。分支：`codex/reliable-scansplit`。基线：`bb8cca6`（v1.11.1）。

交付：独立运行目录 `D:/ScanSplitPDF-Reliable-1.12.0`、同名 ZIP。双击目录中的 `ScanSplitPDF.exe`，保留 `_internal` 与全部运行文件；旧版本未覆盖。源代码提交及程序 SHA-256 见随包 `版本与验证.json`。

## 1. 修改前的 UI 问题

- 待处理事项散在分组、方向和边界窗口中，用户难以知道该从哪里继续。
- 完成数量、人工确认和规则接受区分不足；预检与导出后的实际校验容易混淆。
- 名称面板暴露过多页码操作与候选，来源不一定对应当前文字，确认操作容易滚出视野。
- 缩略图信息过密，窄窗口部分步骤与操作被裁切；页面适应模式重复计算 DPI，可能只显示局部。
- 任务失败原因依赖弹窗和日志，不便之后定位。普通设置包含检测参数，增加使用门槛。

## 2. 修改内容与原因

增加只读 `presentation.py`，将已有状态翻译成产品语言，不运行算法、不确认结果。顶部五步显示当前步骤、完成量和剩余量。

右侧检查中心与名称页签共享原有空间。检查中心汇总方向、交界、文件范围、标题、填报单位、任务/预览错误和导出阻断；点击定位，双击或按钮开始处理，导航不会应用建议或确认字段。

边界审核明确两张图各自原页号与关系；可审核已建立的全部交界。“稍后处理”移动到下一项但保留待确认状态；依据只展示实际保存的证据，未记录的不编造。

名称采用只读信息卡片，显示当前文字的来源、自动/人工状态及最终文件名，点“修改”才展开编辑。候选与页码操作按需展开；底部固定“确认当前文件名称并看下一份”，跟随当前编辑文件，避免确认错组。

缩略图简化为确认、待确认和新文件等提示；预览显示文件归属、保留/排除状态、原件方向、实际调整和未应用建议。修复整页适应的 DPI 换算，并保证常见窄窗口步骤与按钮可见。

处理进度显示阶段和数量，失败原因留在检查中心。普通设置仅显示命名与保存位置；重置不改检测参数。导出按钮继续固定在主窗口底部右侧。预检、实际覆盖/保真及源文件检查分开；取消和未完成不显示全批通过；改标题、方向、拆分或模板会使旧结果失效，新导出失败不会延用上次成功状态。

保持 Tk 技术栈、本地离线处理与所有核心算法。必要的非 UI 变更仅为 `Group` 的人工参与方式展示字段、快照保存/恢复，以及 `grouping.py` 两行唯一对应迁移复制，不改变拆分或命名决策。OCR、拆分、命名、导出、保真验证算法文件相对基线无变更。

## 3. 用户流程变化

旧流程：检测/拆分 → 分散查看方向、补拆和分组状态 → 在大量输入框与页码操作中找名称问题 → 查找导出入口。

新流程：选择 PDF → 开始自动分析 → 检查中心处理方向与交界 → 核对文件范围 → 名称卡片核对标题与填报单位 → 固定按钮确认下一份 → 底部“导出 PDF…”核对清单并保存 → 检查实际导出结果。

用户始终可看到哪些结果由规则产生、哪些经过人工确认、还剩多少事项，以及将生成的文件名；证据不足继续要求确认，不提高自动接受程度。

- 新增测试覆盖状态计数、检查中心、跨文件/字段定位且不确认、来源与人工状态、手改名称经过重新分析仍保留、跳过仍待确认、原方向与建议、内部空白、导出前后及取消反馈、所选范围、旧检查失效、任务失败回滚、窄窗口和固定确认按钮、设置与模板变化。
- 开发中暴露的引导文案兼容、测试加载 API 错误均已修复；布局检查发现的顶部裁切、DPI 页面裁切、确认按钮滚出视野均已修复并补充几何/交互回归。
- 一批实际 Tk 窗口截图检查与一批修正确认覆盖 1400×820、1100×680，随后固定栏与模板变化用几何/交互测试验证。随包仅放仍对应当前实现的检查中心、交界审核截图。
- PyInstaller 构建成功，部署后 EXE `--selftest` **退出码 0**：实际运行中文 OCR/填报单位提取、渲染、无损导出、页面记录与源文件哈希核对。包结构、模型、源码提交、EXE 和 ZIP 核对记录见随包元数据。
- 本轮合成 UI 与功能回归不能证明真实业务文件完全自动正确；没有重新运行历史大规模 OCR 场景，也不引用其百分比作为本轮成绩。

## 5. 真正影响体验的后续事项

1. 用用户的真实混合扫描件验收：分别统计自动拆分正确率、人工确认后的最终完整性、填报单位准确率和确认次数；专门测几百页文件的等待与预览响应。
2. 增加整理项目保存/恢复，防止关窗后需要重新整理；当前版本只在会话内保护人工决定，关闭前应完成导出。
3. 在另一台干净 Windows 机器验证离线启动与字体/DPI 兼容性。
4. 如后续允许扩展状态记录，可保存自动边界的结构化依据；本轮明确显示未记录情况，不改算法补造证据。
