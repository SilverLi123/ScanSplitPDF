# v1.16.0 末页右下角单位扫描交付报告

日期：2026-10-12。分支 `codex/reliable-scansplit`；基线 `2773da4`（v1.15.0，407项）。

## 问题与实现

此前产品的填报单位路径只接受明确“填报单位”标签，末页只有单位名称的落款被忽略。用户最新授权扫描末页右下角，本轮增加高清区域提取，优先明确标签，无标签落款填入待确认候选，用户核对即可确认或修改。

- 扫描最后一张实际保留的内容页，跳过末尾空白/输出排除页。按当前已确认方向渲染2400px图像，扫描右侧65%、底部35%；不选择新方向，不修改原页。
- 复用现有明确标签识别。无标签机构名需满足右下角、独立文字行、机构后缀、基本文字/位置/分数筛选；正文措辞、日期页码、场所名与附近其他单位角色标签不作为落款。
- 明确标签优先，同文本优先保留标签证据，不同候选全部保留。局部明确标签与整页标签不同则不自动确认；无标签落款无论分数多少都不自动确认。
- 名称卡片显示落款来源与待确认提示；检查中心定位末页实际文字框，查看和导航不会确认。边界未确认仍先核对首页和范围。
- 人工填写/选择/确认的字段不被覆盖。取消不发布未完成名称；局部失败不把单位显示为规则确认。缓存独立且有界，空结果不缓存。

仅新增 `unit_region.py`，调整 `autoname.py` 编排与 `presentation.py/ui_widgets.py` 展示。没有修改 `ocr.py`、模型、`ocrfields.py`、`splitctx.py`、`jointsplit.py`、方向算法、`exporter.py` 或 `verify.py`。

## 流程

导入 → 自动分析 → 检查拆分 → 确认名称 → 导出。名称阶段增加：点击单位问题或“查看来源”直接核对末页右下角；无标签落款从留空手工输入改为预填候选后确认。拆分未可靠的文件仍不能先确认名称并正式导出。
