# v1.15.0 空白自动删除交付报告

日期：2026-10-12。分支 `codex/reliable-scansplit`，基线 `d4b44d5`（v1.14.0，366 项测试）。

## 修改前的问题与本轮结果

此前所有空白默认保留；删除与分隔含义混用，内部空白即使没有内容也需要手工处理。用户最新要求明确空白需要删除，本轮改为自动从输出排除，通过独立页面去向记录保证可追踪。

一次自动分析现在完成明确空白删除、原有页码拆分和可靠分组的名称提取。用户核对异常和名称后导出；原 PDF 不变。删除内部空白不会另起文件，也不等于其前后交界已确认。

本轮减少了空白删除操作，但真实混合件的交界自动化不足仍未全面解决。

## 实现与界面

- `blankpolicy` 使用2400px整页含页边图像和文本层复核，复用现有空白分类器的默认保守阈值。证据完整且通过才自动删除；疑似、浅色内容、文本层、页边标记或检查失败先保留。
- `PageState.omitted_blank` 与 `separator/split_before` 分离；`Group.pages` 返回实际输出原页列表。首尾/连续空白不生成空 PDF，内部删除不创建新交界。
- 缩略图和预览区分规则自动删除、人工删除；名称卡片显示实际输出页数。右键可以恢复或人工删除输出页，删除不改变交界；人工决定、撤销及重新分析保护。
- 无印刷页码候选时，明确空白与强首页标题/明确填报单位及信息变化可独立支持拆分；不覆盖弱页码、冲突、续表或附件证据。该条件分支经过单元及编排测试，新增实际中文样本因字段分数不足仍待确认，没有把计划中的自动拆分冒称为已实现的样本效果。
- 删除页后，交界影响范围跨过已删除页，未确认交界阻止两侧自动命名与导出；直接 API、关闭 strict、部分导出也不能绕过。

因输出页列表可以不连续，本轮确实修改了 `exporter.py` 的页面迭代和映射，以及新增空白排除依据校验。原页复制、原件防覆盖、源哈希、内容/图像保真、重复/遗漏和取消标准不降低。逐页 JSON 记录 `excluded_blank_rule` / `excluded_manual`，附原页号、输出页号和空白检查证据；内部原第3页成为输出第2页时正确记录。

OCR 引擎/模型、字段与命名算法、原方向算法、原空白分类器、页码阈值和 `verify.py` 未改变。

## 验证

最终完整回归：**407 passed in 162.80s**，0 失败、0 跳过。新增 `test_blankpolicy.py` **41 项**，没有删除旧测试。覆盖空白/阴影/背面、页边内容/短文本层/印章/表格保护、失败/取消/人工优先、非连续输出保真及去向、空组、恢复/重分析、交界独立规则、跨删除页的命名与部分导出阻断，以及界面依据与实际删除一致。

期间修复：旧测试替身没有接受新增 `remove_blank` 参数；新 Tk 测试初始化缺少渲染器；删除页后的交界影响范围遗漏；待确认原因仍显示“空白保留”。旧断言保留，后两项新增明确回归。一次定向运行出现 Tk 变量析构线程警告，最终完整回归未再出现；长期 GUI 稳定性仍未验收。

真实离线 OCR 使用 v1.14 保存的同一批16页PDF，SHA-256 一致：

| 场景 | 原页 | 自动输出分组（原页号） | 自动删除 |
|---|---:|---|---|
| 无空白、可靠页码重启 | 4 | [1,2]、[3,4] | 无 |
| 空白加可靠页码重启 | 5 | [1,2]、[4,5] | 原第3页 |
| 内部空白、连续页码 | 3 | [1,3]，同一份文件 | 原第2页 |
| 低分中文短页脚 | 4 | 全部保留，三处交界待确认 | 无 |

三个清晰场景自动提取五份名称；仍需最终名称确认，验收明确模拟这一步，没有模拟方向、边界或删除确认。五份导出包含10个原内容页，另2原页有空白删除记录，映射/保真和原文件哈希通过。

另加3页无页码中文样本：中间明确空白自动删除，但首页字段低分，交界仍待确认，不自动命名。另加1页仅在页脚有标记的反例：不删除。总计20页、49.52秒，非性能基准或业务准确率。

历史11页文件只读诊断：54.7秒；自动删除明确空白第3、7、8、11页，保留原第1、2、4、5、6、9、10页。原件不变，所有11原页恰好有一个去向；3页方向和4处交界待确认，自动命名0份。未导出、未复制该用户原件；尚无已核实的正确业务交界，不计准确率。
