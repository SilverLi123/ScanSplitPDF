# ScanSplitPDF v1.13.0 页码拆分交付报告

日期：2026-10-12。分支：`codex/reliable-scansplit`。基线：`1eb3a1e`（v1.12.0）。独立运行目录 `D:/ScanSplitPDF-Reliable-1.13.0` 与同名 ZIP；旧版本保留。源码提交与 EXE 校验值见随包 `版本与验证.json`。

## 修改与依据

之前同名表格出现页码重启仍须人工拆分，空白上下文与无空白判断缺少统一比较；自动交界也没有保存具体页码依据。

本轮增加严格印刷页码证据与相邻内容页判断。有空白时比较两侧；没有空白也能按可靠页码重启自动拆分，不要求标题变化。标题、填报单位、续表和附件用于辅助与检查矛盾，不能用正文数字替代页码。没有新增条码功能。

| 证据 | 处理 |
| --- | --- |
| 可靠 2→1，无空白且无矛盾 | 从后页拆分，支持同一表名 |
| 可靠 2→空白→1 | 拆分，空白仍保留在前份 |
| 可靠 1→空白→2 | 同份保留，空白标为内部空白 |
| 跳号、低分、缺失或多个页码候选 | 人工确认；低分连续数字也不能显示为可靠归属 |
| 续表/附件重启、总页数未到末页、连续页码但标题/单位冲突 | 人工确认 |
| 无空白 1→1，前份总页数未知 | 人工确认；明确前份共1页才可判断单页文档重启 |

自动分析清除过时自动拆分点，人工边界、空白保留/排除、方向和名称继续优先。证据记录原页号、空白列表、两侧印刷页码与实际原因；撤销快照深拷贝，兼容旧快照。交界复核与预览只读显示实际依据，不会因查看而确认。

调研参考：[pdf_doc_splitter 的页码与标题评分](https://github.com/varma-kamadi/pdf_doc_splitter/blob/main/pdf_splitter/boundary.py)、[scanprep 的条码与空白处理](https://github.com/baltpeter/scanprep/blob/master/scanprep/scanprep.py)。它们没有直接提供本项目所需的保守页码比较、保留空白和人工状态保护，故自行实现，未复制外部代码。scanprep 默认删除空白的行为不采用。

实际变更：`pagenum.py`、新增 `jointsplit.py`、统一入口 `pipeline.py`，以及模型证据快照、只读展示和版本号。OCR 引擎、图像空白检测、旧上下文规则、方向算法、命名/填报单位算法、分组迁移、导出和保真验证相对基线无变更。

## 验证

- 完整 `pytest -q`：**321 passed in 171.64s**，0 失败、0 跳过。基线 275 项全部保留，新增 `test_jointsplit.py` 45 项及 UI 证据展示 1 项。
- 覆盖页码格式、日期/年份/表格数字/正文不误用、识别分数不足、页眉页脚冲突；有/无/多个空白、同名表格、内部空白、续表/附件、单位冲突、总页数与单页歧义；人工决定与名称保护、过时自动点清除、方向未确认不拆、每原页恰好一次及实际无损导出；证据撤销隔离及 UI 查看不产生确认。
- 真实本地 OCR 验收 `tools.acceptance_pagination.py`：4 份图像型合成 PDF，共 16 页，32.64 秒。三个清晰英语印刷页码 `Page N of 2` 场景在显式模拟人工确认方向后，**不作任何人工边界修正**，自动得到无空白分组 `(1–2,3–4)`、空白重启 `(1–3,4–5)`、内部空白 `(1–3)`；导出 5 份文件，12 原页全保留，原始内容保真和源 SHA-256 通过。
- 中文短页码低分场景保留全部 4 页、不自动拆，3 个交界待确认；补齐名称后仍由边界状态阻止正式导出。初次自动分析中 14 个内容页均有方向待确认，之后方向和名称是明确模拟人工确认，不能将最终分组声称为端到端全自动结果。
- 开发验收曾发现小字号中文页码虽读出数字，但分数不足；英语页脚也受字体、JPEG 与页面内容影响。保留阈值及待确认行为，另外构造清晰英语页码测试自动路径，并保留低分中文负向验收。未降低阈值来让测试通过；当前 OCR 分数不是校准正确率。
- PyInstaller 构建成功，新运行目录 EXE `--selftest` 退出码 **0**，覆盖本地模型、中文 OCR、明确填报单位、渲染、原页导出、去向记录与源 SHA-256。自检不直接覆盖新页码算法，该算法由上述独立验收及回归测试验证。嵌入模块和 ZIP 核对见随包元数据。

复现：`python -m pytest -q`；`python -m tools.acceptance_pagination --out work/acceptance/pagination-1.13.0`；`python -m PyInstaller scansplit.spec --noconfirm`；新包 `ScanSplitPDF.exe --selftest`。

## 用户流程与限制

导入 → 自动分析 → 在检查中心先确认方向、再处理不确定交界 → 核对每份文件范围 → 确认标题与明确填报单位 → 底部“导出 PDF…”。可审核已自动建立的全部交界，空白排除始终需要单独明确操作。

本轮减少可靠页码场景中的手工拆分，不承诺所有扫描件只需少量确认。中文短页脚低分、方向待确认、无页码或重启歧义仍可能带来较多检查；真实业务样本自动准确率和几百页实际体验尚未验收。关闭后项目恢复、另一台干净 Windows 机器验证仍未完成。后续应先用真实失败样本统计漏拆/误拆、方向确认量、页码可读率和最终完整性，再决定是否改进页码区域 OCR。
